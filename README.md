# kintone 一覧行クリック遷移プラグイン

kintone の PC 版アプリで、表形式の一覧（`viewType === 'list'`）の行をクリックすると、レコード詳細画面へ遷移するプラグインです。

## このリポジトリの構成（プラグインと全体カスタマイズは別物です）

このリポジトリには、目的が近い **2つの別々の成果物** が入っています。ファイル・導入方法・対象範囲が異なり、互いに依存しません。片方だけでも、両方でも使えます。

| | ① アプリ用プラグイン | ② ポータル用 全体カスタマイズ |
| --- | --- | --- |
| 場所 | `plugin/`（ビルドして `dist/plugin.zip`） | `customize/portal-row-click.js`（単一ファイル） |
| 導入先 | システム管理の「プラグイン」で読み込み、アプリごとに追加 | システム管理の「カスタマイズ/API」→「JavaScript / CSSでカスタマイズ」にアップロード |
| 対象画面 | アプリ本体のレコード一覧（PC・表形式） | ポータルの一覧（PC・モバイル） |
| 対象者・設定 | 設定画面あり（対象者・一覧・クリック範囲など） | 設定なし（全アプリ・全ユーザーに一律適用） |
| 詳細 | 本ページの「設定項目」「挙動の仕様」 | 本ページの「ポータル行クリック遷移（全体カスタマイズ）」 |
| テスト | `test/core.test.js`、`test/dom.test.js` | `test/portal.test.js` |

- ②は①のコード（`plugin/js/core.js` など）を使いません。逆も同様です。
- ①をビルドしても②のファイルは `dist/plugin.zip` に含まれません。②は `customize/portal-row-click.js` をそのままアップロードします。
- ①と②は発火する画面が違うため（アプリ一覧／ポータル）、同じ環境に両方入れても競合しません。

## 対象範囲

以下は **① アプリ用プラグイン** の対象範囲です（②の範囲は「ポータル行クリック遷移（全体カスタマイズ）」の節を参照）。

- 対象: PC 版アプリ本体のレコード一覧（表形式）
- 対象外（①のみ）: モバイル、ポータル・スペースの一覧、カレンダー、カスタマイズビュー。ポータルの一覧は②が担当します

## セットアップ

```sh
npm install
npm test            # 単体テスト・DOM テスト
npm run build       # dist/plugin.zip を生成
```

- ビルドは `@kintone/cli`（`cli-kintone plugin pack`）を使います。
- 秘密鍵は `.keys/private.ppk` に自動生成されます。同じプラグイン ID を保つには、この鍵を保管してください。鍵は `.gitignore` 済みです。コミットしないでください。
- 別の鍵を使うときは、環境変数 `KRC_PRIVATE_KEY` に鍵ファイルのパスを指定します。
- 生成した `dist/plugin.zip` を kintone システム管理でプラグインとして読み込みます。

## 設定項目

| 項目 | 選択肢 |
| --- | --- |
| 対象者 | 全員（既定）／組織・グループ指定（下位組織を含めるか選択可） |
| 対象一覧 | すべての表形式一覧（既定）／指定した一覧 |
| クリック範囲 | 行全体（既定）／指定フィールドの列のみ |
| 項目種別ごとの動作 | リンク、ルックアップ、添付ファイル、ユーザー・組織・グループ選択、作成者・更新者・作業者、リッチエディター、テーブルそれぞれについて「リンク先（標準動作）優先」（既定）／「レコード詳細優先」 |

組織・グループ・一覧・フィールドの一覧を API から取得できないときは、コードをカンマ区切りで入力する欄に切り替わります。

## 挙動の仕様

- クリックは document で1回だけ受けます。ページ送り・絞り込み・ソートで一覧が再描画されても、二重には登録されません。
- 行内（対応済みセルの外）に標準の詳細リンクがあり、その `href` が同一オリジンの `/k/(guest/{id}/)?{appId}/show#record={数字}` であれば、それを使って遷移します。リンク型・リッチエディターなど対応済みセルの中のリンクは標準リンクとして扱いません（レコード番号列を除く）。標準リンクが無いときは、`kintone.app.getFieldElements` とイベントのレコード配列の `$id` から URL を組み立てます。
- 行の `$id` と標準リンクの ID が食い違うときは、セルとレコードの並びがずれている可能性があるため、遷移せず標準動作のままにします。
- テーブル列（対応外の列）は、アプリに SUBTABLE 型フィールドがあり、クリック範囲が「行全体」のときだけ遷移対象です（標準リンク・チェックボックス・ボタンを含む列を除く）。その列にもカーソルとホバー色を付けます。
- 標準リンク経由のときは一覧の前後レコード移動が使えます。組み立て URL 経由では使えないことがあります。
- 次の場合は常に標準動作のままです。
  - 右クリック
  - Shift＋クリック（遷移せず標準動作のままです。リンク上なら新しいウィンドウで開きます）
  - チェックボックス、行末の編集・削除などのボタン、標準の詳細リンク列
  - インライン編集中の行
  - 文字列を選択しているとき（同じ行内）
  - 「リンク先優先」の種別で、リンクやボタンなどの操作要素をクリックしたとき
- Ctrl／Cmd＋クリック、中クリックは新しいタブで開きます。
- 対象者の判定が終わり、対象と決まったときだけ、範囲内のセルに指のカーソルを付けます（元のインライン cursor は戻せるよう保存します）。対象外・判定待ち・取得失敗では付けません。
- 他のハンドラーが既に `preventDefault` したクリック、および一覧の表の外（対応するセルを持たない行）は無視します。
- 対象者の制御はアクセス制限ではありません。対象外のユーザーは標準動作のままになるだけです。
- 所属の取得に失敗したとき、またはゲストユーザーのときは、対象者を「指定」にしていると標準動作のままになります。
- 対象者の判定が終わるまで（一覧表示の直後だけ）は標準動作です。
- ルックアップの設定を変えたときは、このプラグインの設定画面を開いて保存し直してください（ルックアップのフィールドコードを保存時に取得するため）。
- 失敗時は標準動作に戻る設計です。例外はすべて握りつぶし、遷移しない側に倒します。

- [ ] 標準詳細リンクの DOM 構造（行頭のリンク・ボタン列）が想定どおりで、除外判定が正しく働く
- [ ] インライン編集・ソート後の再描画でも、二重遷移や遷移漏れがない

- [ ] ゲストスペースでの挙動

- [ ] `getFieldElements` の各配列の並びと `event.records` の並びが、ソート・ページ送り・インライン編集の保存後も一致する（食い違うと遷移しない）
- [ ] レコード番号列（`$id`）のセルに `getFieldElements` が値を返すか、その中に標準の詳細リンクがあるか
- [ ] 標準リンク経由のときに前後レコード移動が使える／組み立て URL 経由のときの挙動

- [ ] 行末の編集・削除ボタン、インライン編集の保存・キャンセルの実要素が button か a/span か（除外判定が効くか）
- [ ] 「レコード詳細優先」のとき、ユーザーのポップアップやファイルのプレビューが遷移と同時に動かない
- [ ] 一覧から詳細へのページ内遷移後に、関連レコード一覧などの tr に反応しない
- [ ] インライン編集でない行に常時表示の input（checkbox・hidden 以外）が無い
- [ ] Windows／Chrome の中クリックの自動スクロールと `auxclick` の `preventDefault`、Mac の Ctrl＋クリックとの兼ね合い
- [ ] `setConfig` 完了後の `../../flow?app=` への遷移先が現行の kintone で正しい

## ポータル行クリック遷移（全体カスタマイズ）

### 概要

`customize/portal-row-click.js` は、このプラグインとは別物の「JavaScript/CSS でカスタマイズ」用の単一ファイルです。ポータルに表示される、通知・未処理一覧など行内にレコード詳細リンクを含む一覧（tr / li / `[role="row"]` / `[role="listitem"]` の行）で、行のどこをクリック・タップしてもレコード詳細へ遷移します。プラグインの設定画面はなく、全アプリ・全ユーザーに一律で適用されます。既存プラグイン（一覧画面用）とは独立していて、競合しません。

### アップロード手順

1. 「システム管理」→「カスタマイズ/API」→「JavaScript/CSSでカスタマイズ」を開きます。
2. 「PC用のJavaScriptファイル」と「モバイル用のJavaScriptファイル」の両方に、同じ `customize/portal-row-click.js` をアップロードします。
3. 保存して、ポータルを開いて確認します。

### 挙動

- 行内にレコード詳細へのリンクが「ちょうど1件のレコード分」あるときだけ、行全体が遷移対象になります（同じレコードへのリンクが複数あっても1件扱い）。リンクが無い行、複数のレコードへのリンクがある行は何もしません。
- 通常のクリック・タップは同一タブで遷移します。Ctrl／Cmd／Shift＋クリックと中クリックは新しいタブで開きます。Shift＋クリックはテキスト選択の状態に関わらず新しいタブで開きます。
- リンク・ボタン・入力欄・ラベル・`summary`・`role="button"` / `link` / `checkbox` / `menuitem` / `tab`・`tabindex`（-1 以外）付き要素・編集可能領域のクリック（行の内側にあるものだけが対象で、行自身や外枠が tabindex / role を持っていても遷移します）、見出し行、テキスト選択中、先行して `preventDefault` されたクリックは対象外です。
- PC ではマウスが 10px を超えて動いたとき（ドラッグ・Shift＋ドラッグでの選択）、モバイルでは指が 10px を超えて動いたとき（スクロール）は遷移しません。
- 同じ行にマウスが留まっている間に行内のリンクが差し替わった場合、カーソル表示（pointer）は行を出入りするまで更新されません（遷移の可否には影響しません）。
- ポータル画面（`/k/` 直下など）でのみ動作します。スクリプトの読み込み時に `document` へキャプチャ段階で登録し、クリック（mouseover）のたびにポータルの URL かどうかを判定するため、SPA 遷移で別画面に移ったときは何もしません。二重登録は `<html>` の `data-krc-portal-bound` 属性で防ぎます（`<body>` の `data-krc-bound` は診断専用の印です）。
- click はキャプチャ段階で処理して `preventDefault` しますが、`stopPropagation` はしないため、他のハンドラーも引き続き実行されます（`preventDefault` 済みの状態で届きます）。
- カーソルは、遷移できる行にマウスを乗せたとき（モバイルはタッチ開始時）だけ pointer になります。

### 制約

- iframe で埋め込まれた内容は対象外です。
- 遷移先は、行内のリンクの URL（同一オリジンの http/https のみ）をそのまま使います。URL は組み立てません。

### 要実機確認

- [ ] 標準一覧の DOM（`getContentSpaceElement()` は使わず `document` へ委譲しています。ポータルの行が `tr.recordlist-row-gaia` で、詳細リンクが `a.recordlist-show-gaia` の構造か、行が tr / li / role=row か）
- [ ] click をキャプチャ段階で処理するため、行内の独自 `onclick` 要素（標準部品を含む）が動かなくなっていないか（行内に標準のハンドラーがあっても、遷移が優先され `preventDefault` されます）
- [ ] ポータルを開いた状態で `<html>` に `data-krc-portal-bound`、`<body>` に `data-krc-bound` が付いているか（読み込み・登録の診断用）
- [ ] 標準 UI 部品（通知の既読ボタン、メニュー、タブ、チェックボックスなど）での誤遷移が無いか
- [ ] Firefox で `auxclick` 内の `window.open`（中クリック・Shift＋クリック）がポップアップブロックされないか
- [ ] ポータルの URL 形（`/k/`、`/k/#/portal`、ゲスト `/k/guest/<id>/`、モバイル `/k/m/`）が判定に合っているか
- [ ] モバイルのゲストスペース URL の並び（`/k/guest/<id>/m/<app>/show` か `/k/m/guest/<id>/<app>/show`）。両方に対応していますが、実際の形を確認してください
- [ ] モバイルで PC 形式のリンクを踏んだときのリダイレクト動作
- [ ] ポータルの再描画後も遷移・カーソルが効くか
- [ ] 行の外側を包む `label` / `a` は無視する設計です（行をクリックすると、label 経由のチェック切替は取り消されて遷移が優先されます）。実機で問題ないか
